# 打包与发布

> 三种获得可运行应用的方式：源码直接运行（开发用）、本地一键构建（自用/测试）、CI 自动发布（正式发版）。

## 一、三种方式对比

| 方式 | 命令 | 产物 | 适用 |
|---|---|---|---|
| 源码运行 | `python run.py` | 无产物，直接跑 | 日常开发调试 |
| 本地构建 | `python build.py` | `dist/BilibiliDownloader.exe`（Win）或 `dist/BilibiliDownloader.app`（Mac） | 自用、发前验证 |
| CI 发布 | 推 tag `git tag v1.2.0 && git push --tags` | 双平台产物自动挂到 GitHub Release | 正式发版 |

## 二、本地构建

```bash
pip install -r requirements.txt pyinstaller
python download_deps.py          # 准备 bin/（缺失时 build.py 也会提示）
python build.py                  # 一键构建 + 校验
python build.py --no-clean       # 迭代时跳过清理，更快
```

**build.py 做了什么**：检查 bin/ → 清理 build/dist → 调 PyInstaller（用 `BilibiliDownloader.spec`）→ 校验产物。

## 三、产物形态

| 平台 | 形态 | 用户如何使用 |
|---|---|---|
| Windows x64 | **onefile 单 exe**（约 130MB） | 双击运行，无需安装 |
| macOS arm64 | **.app 打成 zip** | 解压后拖入 Applications；未签名，首次打开需放行（见下） |

取舍说明：Windows onefile 首次启动慢 2-4 秒（解压到临时目录），换"单文件最省事"；macOS onefile 启动更慢且易被误报，故用 .app。需要 Intel 版本时在 CI 矩阵加 `macos-13`，本地则要在 Intel 机器或指定 `target_arch` 构建（PyInstaller 不支持交叉编译出另一架构的完整产物）。

## 四、macOS Gatekeeper 放行（应用未签名）

方式一：系统设置 → 隐私与安全性 → 找到被拦截的提示 →「仍要打开」。

方式二（命令行）：

```bash
xattr -cr /Applications/BilibiliDownloader.app
```

## 五、CI 发布流程

1. **升版本号**：只改 `bilidownloader/__init__.py::__version__`（单一真源，spec 的 macOS Info.plist 会自动读取）
2. **更新 CHANGELOG.md**
3. 打 tag 并推送：
   ```bash
   git tag v1.2.0
   git push origin v1.2.0
   ```
4. GitHub Actions 自动：装依赖 → 下载 bin/ → 双平台构建 → smoke check → 挂到 Release
5. 手动触发（不发布，仅供测试）：Actions 页面 Run workflow，产物在 workflow artifacts 里

## 六、发布前产物校验清单（6 项，缺一不可）

- [ ] 产物存在且体积 ≥50MB（异常小说明缺 PySide6 或 bin/）
- [ ] `dist/` 内**不含** `data/cookies.txt` 与 `data/settings.json`（凭证红线）
- [ ] 图标资源已随包：启动后侧边栏 21 个 SVG 图标正常显示（缺 assets 会全是空白方块）
- [ ] bin/ 与应用同版本成对（回滚 exe 时必须成对恢复对应 yt-dlp/ffmpeg）
- [ ] 双击能启动到主界面
- [ ] 换肤、设置、登录、下载各走一遍（12 张截图基线对比）

## 七、常见问题

| 问题 | 原因与处理 |
|---|---|
| 产物启动后界面全是空白方块 | spec 的 datas 丢了 `bilidownloader/assets`，检查 spec |
| 提示"未找到 yt-dlp" | bin/ 未随包。注意 **onefile 模式下 bin/ 会被解压到 `sys._MEIPASS` 临时目录，不在 exe 同级**，因此 `downloader._app_bin_dir()` 必须优先查 `_MEIPASS`，再回退 exe 同级与 macOS `.app/Contents/Resources/bin` |
| 构建报 `NameError: name '__file__' is not defined` | spec 由 PyInstaller `exec` 执行，命名空间里**没有 `__file__`**；读文件请用内置变量 `SPECPATH`（spec 第 22 行已如此实现） |
| 产物异常大（>200MB） | bin/ 被打了两份（spec datas + collect binaries）；检查 spec |
| macOS 报"damaged / 无法验证" | Gatekeeper：`xattr -cr` 解除隔离 |
| macOS 报架构不匹配 | Apple Silicon 机器跑了 Intel 构建（或反之），确认产物来源 |
| 杀软报毒 | PyInstaller onefile 的常见误报；可改 onedir 或对发布物做代码签名 |
| PyInstaller 找不到 Qt 插件 | 用 `collect_all('PySide6')`（spec 已有）；不要手动裁剪 |
| CI 构建失败在 download_deps | 网络抖动，重跑即可；ffmpeg 压缩包 >15MB 才有效（脚本已校验） |

## 八、回滚

- **应用二进制**：Release 页保留历史版本产物；exe 与 bin/ 必须同版本成对回滚，错配即功能异常
- **配置**：`data/settings.json` 向前兼容（新键有默认值），回滚无需处理
- **凭证**：`data/cookies.txt` 永不进发布物；若怀疑泄露，用户改密码使旧凭证失效
