面向开发/测试/发布的执行手册。**任何改动在进入发布候选（RC）前必须逐层过门禁，勾选完成才可打包。**

配套文档：[使用说明.md](../使用说明.md)（用户视角）、[开发者指南.md](../开发者指南.md)（架构与踩坑）、`docs/02-交付流程SOP.md`（流程与需求）。

> 环境约定：下文所有命令均在 **Git Bash** 下执行，Python 解释器固定使用项目 venv（已装 PySide6/requests/qrcode/pillow/yt-dlp）：
> `"C:/Users/<你的用户名>/.workbuddy/binaries/python/envs/default/Scripts/python.exe"`
> 为节省篇幅，正文中统一写 `$PY`，首次使用前请先执行：
> ```bash
> PY="C:/Users/<你的用户名>/.workbuddy/binaries/python/envs/default/Scripts/python.exe"
> cd "<项目目录>"
> ```
> 需要复制单行执行时，把 `$PY` 原样替换成上面的绝对路径即可。
> `docs/01-团队协作规范.md` 里写的 `python verify.py` / `python screenshot.py` 与本文的 `$PY verify.py` / `$PY screenshot.py` **完全等价**——前者假定 venv 已激活，后者是免激活的绝对路径写法。两者判定标准一致。

## 0. 门禁总览

| 层级 | 名称 | 载体 | 耗时 | 触发时机 | 判定标准 |
|---|---|---|---|---|---|
| L0 | 静态与导入 | `py_compile` + `import` 冒烟 | <10s | 每次改动 | 退出码 0 |
| L1 | 单元测试 | `verify.py` 第 1/2/4/5 节 | <5s | 改工具函数/主题/设置/命令拼装 | 全 PASS |
| L2 | 集成测试 | `verify.py` 第 3 节（FakeDownloader） | ~20s | 改 `queue_manager.py` | 全 PASS 且 `max_active <= limit` |
| L3 | 端到端 | 手工小体积下载（真实 yt-dlp） | 1–3min | 改 `downloader.py` / 发版前 | 产物文件存在且可播放 |
| L4 | 视觉核对 | `screenshot.py` 12 张截图 | ~15s | 改任一 view / `theme.py` | 12 张齐全、二维码唯一色值=2 |
| L5 | 打包验证 | `dist/BilibiliDownloader.exe` 冷启动 | ~2min | 发版前 | exe + `bin/` 平级可启动 |

**红线**：L0–L2 任意一项失败 → 禁止提交；L3–L5 任意一项失败 → 禁止发版。

## 1. 测试分层细则

### L0 静态 / 导入

- **测什么**：语法正确性、模块可导入、无循环导入、无遗留调试断点。
- **怎么跑**：

```bash
cd "<项目目录>"
$PY -m py_compile run.py verify.py screenshot.py download_deps.py bilidownloader/*.py bilidownloader/views/*.py
$PY -c "import sys; sys.path.insert(0,'.'); import bilidownloader.theme, bilidownloader.downloader, bilidownloader.queue_manager, bilidownloader.app_settings, bilidownloader.login, bilidownloader.qrcode_gen, bilidownloader.gui; print('import ok')"
```

- **判定**：两条命令均退出码 0 且打印 `import ok`。
- **补充检查**：`grep -rn "breakpoint()\|pdb.set_trace" bilidownloader/ run.py` 必须无结果。

### L1 单元测试

- **测什么**：

| 模块 | 关注点 |
|---|---|
| `downloader.py` | `parse_size` / `parse_speed` / `human_speed` / `human_size` / `fmt_duration` 边界；`build_download_cmd` 的画质串、限速、输出模板、`--ffmpeg-location` |
| `theme.py` | `LIGHT/DARK` 令牌齐备（`accent`/`bg_sidebar`/`accent_soft`/`success_soft`/`danger_soft`/`text_icon`）；`resolve(auto/light/dark, system_is_dark)` 三态；`stylesheet()` 无 `{p.` 占位符残留 |
| `app_settings.py` | 写盘→新建实例→读回一致；`proxy_url()` 在 `none/system/custom` 三模式下的返回值；`logged_in` 仅在含 `SESSDATA` 为真 |
| `login.py` | `poll()` 读**内层** `data.code`：`0→success`、`86101→waiting`、`86090→scanned`、`86038→expired`；无 `SESSDATA` 时返回 `failed` |
| `qrcode_gen.py` | `make_qr_pixmap()` 输出唯一色值**恰为 2**、无二次缩放 |

- **怎么跑**：`$PY verify.py`（看第 1、2、4、5 节输出）+ 按需补充断言。
- **判定**：每一 `[PASS]`，结尾输出 `全部通过`，进程退出码 0。

### L2 集成测试（队列状态机）

- **测什么**：`QueueManager` 的 `WAITING→RUNNING→PAUSED/FAILED/DONE` 状态机、并发上限调度、暂停补位、继续续传、失败重试、清空已完成、退出前 `shutdown()`。
- **核心手法**：注入 **FakeDownloader**（`verify.py` 第 31–54 行），不碰网络与真实 yt-dlp，20×0.05s 模拟下载。
- **怎么跑**：

```bash
$PY verify.py    # 第 3 节即 L2
```

- **判定**：
  - `running_count()` 恒 `<= max_concurrent`；
  - `fake.max_active <= limit`（并发**从未**超限，这一条最容易被忽略）；
  - 暂停后状态变 `PAUSED`，且并发位被后续任务补上；
  - 全部任务最终收敛到 `DONE`；`clear_done()` 后无 `DONE` 残留。
- **硬性要求**：等待循环里必须 `app.processEvents()`（`verify.py` 第 90–91 行），否则信号不投递，详见第 6 节。

### L3 端到端（真实链路，人工执行）

- **测什么**：解析（单 P / 多 P）→ 加入队列 → 真实下载 → 字幕/封面/弹幕产物 → 暂停续传 → 失败重试。
- **怎么跑**：

```bash
# 解析可用性（不下载）
$PY -c "
import sys; sys.path.insert(0,'.')
from bilidownloader.downloader import Downloader
d = Downloader(); print(d.available(), d.ytdlp)
info = d.fetch_info('https://www.bilibili.com/video/BV1xx411c7mD')
print(info['title'], info.get('duration'))
"
```

  下载验证在 GUI 里做：选 **480P + 短时长视频**（<2min），产物落在设置里的 `download_dir`。
- **判定**：
  - 输出文件命名符合 `视频标题 [BV号].mp4`；
  - 文件大小 >0 且能被播放器打开；
  - 暂停后继续，**不从 0% 重新开始**（`.part` 断点保留）；
  - 断网重试后任务置 `FAILED` 并显示 `ERROR` 摘要，可 `retry()` 恢复。

### L4 视觉核对

- **测什么**：四页面 × 浅/暗双主题 = 12 张图；重点看卡片边框泄漏、图标染色、二维码可扫性。
- **怎么跑**：

```bash
$PY screenshot.py                     # 输出到 data/screenshots/
ls -la data/screenshots/              # 应为 8 个 png
```

- **判定**：
  - `light-home/dark-home`、`light-detail/dark-detail`、`light-settings/dark-settings`、`light-login/dark-login` 共 12 张；
  - 暗色下文字与背景对比清晰、无黑底黑字；
  - **二维码区域唯一色值 = 2**（见下方脚本，非 2 即为回归）；
  - 无 QLabel 方框泄漏（QLabel 继承 QFrame 的老坑）。

```bash
$PY -c "
import sys; sys.path.insert(0,'.')
from PySide6.QtWidgets import QApplication
from bilidownloader.qrcode_gen import make_qr_pixmap
app = QApplication([])
pm = make_qr_pixmap('https://passport.bilibili.com/x/passport-login/web/qrcode')
img = pm.toImage()
cols = {img.pixelColor(x, y).rgb() for x in range(0, img.width(), 2) for y in range(0, img.height(), 2)}
print('unique colors =', len(cols), '=>', 'PASS' if len(cols) == 2 else 'FAIL', '| size', img.width(), img.height())
"
```

## 2. 现有脚本使用规范

### 2.1 verify.py —— 54 项验收，提交前必跑

> **项数口径**：以脚本实际打印的 `[PASS]` 行数为准，**当前 54 项**。
> 计算依据：`check()` 调用点 52 个，其中 2 个在 `for pal in (LIGHT, DARK)` 循环内（各执行 2 次），故实际执行 `50 + 2×2 = 54`。
> 不要按源码里 `check(` 的出现次数计数（36），也不要沿用早先口播的「34 项」（那是改动前的口径且本身偏差 1）。**项数变化须同步更新本说法。**

| 节 | 内容 | 项数 | 失败时先看 |
|---|---|---|---|
| 1 | 工具函数 `parse_size/parse_speed/human_speed` | 3 | `downloader.py` 正则 |
| 2 | 主题令牌与三态解析、样式表 | 9 | `theme.py` 令牌/stylsheet |
| 3 | 队列调度（并发/暂停/继续/重试/清空） | 9 | `queue_manager.py::_pump/_start/_on_done` |
| 4 | 设置持久化 | 1 | `app_settings.py::save/load`、`data/settings.json` 权限 |
| 5 | yt-dlp 命令拼装 | 4 | `downloader.py::build_download_cmd`、`bin/` 是否缺失 |
| 6 | 静态检查 `self.xxx` 未定义方法 | 1 | 输出会直接给出 `{文件路径: [方法名]}` |

| 7.1 | 换肤（皮肤系统 / Backdrop / 半透明派生） | 16 | `skin.py`、`theme.with_alpha`、`gui.py::Backdrop` |

- **失败输出格式**：结尾打印 `失败 N 项: ['xxx', ...]`，**退出码 1**（可直接挂到 CI / pre-commit）。
- **定位三步法**：
  1. 看节号 → 定位模块（对照上表）；
  2. 看 `[FAIL]` 后的 detail（如 `running=3 max=2`），直接暴露超限数值；
  3. 第 6 节失败会打印缺失方法字典，按文件逐个补齐或加入 `qt_builtin` 白名单。
- **副作用提示**：第 4 节会**真实改写** `data/settings.json`（`max_concurrent` 4→3）。若你要保留本机设置，先备份：
  ```bash
  cp data/settings.json /tmp/settings.bak && $PY verify.py; cp /tmp/settings.bak data/settings.json
  ```
- **无窗口环境**：加 `QT_QPA_PLATFORM=offscreen` 前缀（CI 推荐）：
  ```bash
  QT_QPA_PLATFORM=offscreen $PY verify.py
  ```

### 2.2 screenshot.py —— 视觉回归，改 UI 必跑

- **用法**：`$PY screenshot.py [输出目录]`（默认 `data/screenshots`）。
- **机制**：强制先亮色后暗色两轮（`screenshot.py` 第 24/55 行），每页 `QTimer.singleShot(300)` 后 `win.grab()`，**不阻塞主线程**——所以不能用 `time.sleep` 替代。
- **退出前**调用 `view_login.stop_worker()` 再 `app.quit()`（第 66–67 行），否则登录轮询线程会拖住进程。
- **核对方式**：把本次 12 张与上一版基线逐一对比；**登录页二维码必须能真机扫出**（唯一色值测试只能保证像素，最终以手机扫码为准）。

## 4. Bug 分级与响应

| 级别 | 定义 | 本项目示例 | 响应时限 | 处理流程 |
|---|---|---|---|---|
| **P0 致命** | 阻塞核心链路、数据/凭证安全、无法启动 | ① 应用启动即崩溃；② 打包 exe 双击无反应；③ `data/cookies.txt` 被提交进仓库；④ 下载产物损坏或写到错误路径；⑤ 退出时 QThread 崩溃 | **立即停工定位，2h 内给出修复方案，当天修复** | 冻结发布 → 建单 → 修复 → 全量回归（L0–L5）→ 双人复核 |
| **P1 严重** | 核心功能不可用或结果错误 | ① **扫码一直显示"等待扫码"**（读了外层 `code`）；② **下载进度卡住不动**（无事件循环/信号未投递）；③ 暂停后继续从头下载；④ 并发上限失效导致被风控；⑤ 设置保存后重启丢失 | **24h 内修复** | 当迭代修复 → 补一条回归用例进 `verify.py` → 重跑对应层 |
| **P2 一般** | 体验受损但有绕行方案 | ① 按钮错位/间距异常；② 暗色下某处对比度不足；③ 截图与设计稿偏差；④ 文案/提示语歧义；⑤ 二维码偏小需贴近扫 | **3 个工作日内** | 排入下个迭代 → 改 UI 必跑 `screenshot.py` 留基线 |
| **P3 轻微** | 不影响使用 | ① 错别字；② 缺 tooltip；③ 日志冗余；④ 图标风格不统一 | **下个迭代顺带处理** | 记录即可，可批量清理 |

**通用流程**：发现 → 按上表定级 → 建缺陷单（模板见 5.2）→ 修复 → **补一条回归用例**（P0/P1 强制）→ 重跑受影响层 → 关闭。
**争议处理**：定级有分歧时按高一档执行；P0/P1 必须同时通知主理人与架构师。

## 6. 常见假故障排查表

> 现象看着像 Bug，实为机制或用法问题。遇到先查这张表，再决定是否建单。

| # | 现象 | 真正原因 | 排查动作 |
|---|---|---|---|
| 1 | 退出程序时**进程直接崩溃**（无 traceback） | QThread 运行中销毁 | 确认 `MainWindow.closeEvent` 调用 `manager.shutdown()`（`gui.py` 第 603–607 行）；测试脚本里在销毁窗口前先 `pause_all()` 并等 `running_count()==0` |
| 2 | 队列**"卡死"**、任务永远不结束、像死锁 | 无 Qt 事件循环时跨线程信号不投递 | 等待循环里必须 `app.processEvents()` 或 `app.exec()`，不能只 `time.sleep()`；`verify.py` 第 90–106 行是标准写法 |
| 3 | 二维码发虚/变形、**手机扫不出** | 二次缩放或把 PIL 缓冲直接给 QImage | 走 `qrcode_gen.make_qr_pixmap()`（原生整数倍渲染 + PNG 编解码）；用唯一色值==2 脚本验证 |
| 4 | 每个文字标签都出现**输入框式方框** | QLabel 继承 QFrame，样式泄漏 | 卡片样式必须 `QFrame#Xxx {}` 限定 + `QFrame#Xxx QLabel {background:transparent;border:none;}` 清除 |
| 5 | **扫码后一直"等待扫码"** / 登录成功但凭证为空 | B站 poll 接口外层 `code` 恒为 0 | 必须读**内层** `data.code`（0/86101/86090/86038）；成功态还需校验 `SESSDATA` 存在 |
| 6 | 打包后提示**"未找到 yt-dlp"** | `bin/` 未与 exe 平级 | `resource_bin_dir()` 冻结时解析到 `exe.parent/bin`；拷贝整个 `dist/` 而非只拷 exe |
| 7 | 界面空白/卡在启动 | 无边框窗口 + `Fusion` 样式未生效或线程阻塞主线程 | 确认 `app.setStyle("Fusion")`；耗时操作（解析/下载/封面）必须走 QThread，禁止主线程阻塞 |
